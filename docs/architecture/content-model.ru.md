# Модель контента (архитектура)

## Что это

Архитектурная реализация [модели контента](../concepts/content-model.ru.md): конкретные формы данных —
`DocumentPayload`, семантические элементы и семантические чанки — которые проходят между стадиями конвейера
`synflux`.

## Почему это нужно

Чтобы уровни извлечения и аннотирования платформы могли развиваться независимо, форма, связывающая их,
должна быть конкретной и устойчивой, а не просто согласованной на концептуальном уровне. Эта страница
документирует эту форму на том уровне детализации, который нужен владельцам модулей для реализации.

## Как это работает

```text
Объектное хранилище (исходные байты)
  ↓  Уровень извлечения (synanton.extraction.v1)
DocumentPayload { elements, headings, tables, page boxes }
  ↓  Кэш парсера synflux (ingestion_cache_chunks)
Семантические элементы (типизированные, с учётом позиции)
  ↓  Чанкер synflux
Семантические чанки { chunk_id, chunk_text_hash, section_path, page_start/end, source_elements[] }
```

Разобранные артефакты кэшируются с `schema_version`, с ключом по хешу контента — повторно принятый,
неизменившийся документ обрывает весь конвейер через шлюз дедупликации `ingestion_cache_source_digests`
прежде, чем что-либо из вышеперечисленного выполнится снова.

## Пример

`chunk_id=18291` несёт `section_path=["3. GPU Execution Plane", "3.1 GPU Gateway"]`, `page_start=3`,
`page_end=3` и `source_elements=["elem_42","elem_43"]` — этого достаточно, чтобы результат поиска мог
сослаться на «§3.1 GPU Execution Plane», а аудит безопасности мог точно знать, для каких извлечённых
элементов было принято решение о классификации.

## Входные данные

`DocumentPayload` с [уровня извлечения](extraction-plane.ru.md).

## Выходные данные

Семантические чанки, потребляемые стадией чанкера [семантического чанкирования](semantic-chunking.ru.md) и,
далее по конвейеру, [уровнем аннотирования](annotation-plane.md).

## Преобразования

Разбор (байты → элементы) → фиксация в кэше → чанкирование (элементы → чанки) → фиксация в кэше, всегда по
правилу «кэш прежде шины»: запись должна успешно завершиться прежде, чем об этом что-либо сообщается
остальной системе.

## Зависимости

Зависит от контракта [уровня извлечения](extraction-plane.ru.md). Кэш с двойной записью на Cassandra у
`synflux` (`ingestion-cache`) — это граница надёжности.

## Изменение и пересчёт

Повышение `schema_version` у кэшированных артефактов требует либо повторного воспроизведения из источника,
либо документированной миграции; см. [Семантическое чанкирование](semantic-chunking.ru.md#change-and-recalculation)
о том, что меняется при смещении границ чанков.

## Безопасность

На этом уровне классификация не выполняется — см. [Безопасность](security.md) о том, где и как она
применяется, сразу после чанкирования.

## Происхождение

Указатель `source_elements` каждого чанка — это механизм, на котором строится
[происхождение](../concepts/provenance.md).
