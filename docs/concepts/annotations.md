# Annotations

## What it is

An annotation is structured interpretation of content — a record of what Synanton *understands* about a
chunk, as distinct from what extraction merely *recovered* from it.

## Why it exists

> **Extraction describes what was recovered. Annotation describes what Synanton understands.**

Separating the two means a classification rule, an entity model, or a tagging dictionary can change and be
re-run without re-parsing a single source document. It also means multiple, even conflicting,
interpretations can coexist and be compared — annotations are first-class, versioned knowledge, not a
side effect of parsing.

## How it works

```text
Annotation
├── Tag
├── Classification
├── Entity
├── Attribute
└── Signal
```

Annotations may be generated by deterministic rules, dictionaries, regular expressions, ML models, LLMs,
external services, custom code, or human operators — the generation mechanism is deliberately separate from
the annotation contract itself. See [Annotation Types](annotation-types.md) for what each category means.

Every annotation carries an identity independent of its producer:

```text
Annotation
├── annotation_id
├── definition_id / definition_version
├── annotation_type, namespace, name
├── target_type, target_id
├── value
├── producer, producer_version
├── confidence
├── provenance
├── processing_run_id
├── created_at / invalidated_at
```

This lets multiple versions of an interpretation — `payment-detection v3` vs `v4` — coexist and be compared
without destroying history.

## Example

A support call chunk is annotated `intent = cancellation`, `sentiment = negative`, `topic = billing`. Each
annotation records which producer created it, at what confidence, and from which processing run — so a
reviewer can later ask "why does this annotation exist?" and get a real answer.

## Inputs

A [chunk](chunks.md) (or another annotation, for [derived annotations](annotation-dependencies.md)), plus
an [annotation definition](annotation-dependencies.md) describing how to produce the annotation.

## Outputs

A versioned annotation record attached to its target, feeding [knowledge projections](knowledge-projections.md),
[search](search.md), and [analytics](analytics.md).

## Transformations

None once created — an annotation is immutable; a changed interpretation produces a new annotation version
rather than mutating the old one.

## Dependencies

Depends on the target it annotates ([chunk](chunks.md) or another annotation) and its
[annotation definition](annotation-dependencies.md). See [Annotation Dependencies](annotation-dependencies.md)
for annotations that depend on other annotations.

## Change and recalculation

Changing an annotation definition's rule or model version triggers [recalculation](../architecture/recalculation.md)
of everything that depends on it — see [Resolutor](../architecture/resolutor.md) and
[Equalix](../architecture/equalix.md).

## Security

Annotations on classified chunks inherit and respect the chunk's classification and representation — an
annotation must not leak an unmasked value that the underlying chunk would not expose.

## Lineage

Every annotation records its producer, producer version, definition, definition version, evidence,
confidence, and processing run — see [Provenance](provenance.md).
